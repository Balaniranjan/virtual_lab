EXPERIMENT 06 Asymmetric Cryptography

Diffie–Hellman Key Exchange: Two-Party Protocol & MitM Vulnerability

Simulate how two communicating parties (Alice and Bob) negotiate a shared symmetric key over an insecure communication channel, and analyze why unauthenticated key exchange is vulnerable to active Man-in-the-Middle attacks.

Key Establishment Foundation: Diffie-Hellman allows two parties who share no prior secret to establish a shared symmetric key. In modern Internet security, Ephemeral Diffie-Hellman (ECDHE) forms the cryptographic backbone of TLS 1.3 forward secrecy.

Aim of the Experiment

To simulate and evaluate the Diffie–Hellman Key Exchange protocol between Alice and Bob, calculating public exchange parameters and matching shared secrets, while analyzing the security vulnerabilities of unauthenticated communication against Man-in-the-Middle (MitM) adversaries.

Key Learning Outcomes

  • Understand the Discrete Logarithm Problem (DLP) in finite cyclic groups.
  • Trace the step-by-step key exchange: public values A = g^a mod p and B = g^b mod p.
  • Demonstrate that both parties arrive at the identical shared secret key: K = g^(ab) mod p.
  • Simulate an active Eve intercepting parameters to understand why digital signatures or PKI are mandatory for authenticating Diffie-Hellman exchanges.

Theoretical Principles of Diffie-Hellman

1. The Discrete Logarithm Problem (DLP)

The security of finite-field Diffie-Hellman relies on the asymmetric computational complexity of modular exponentiation versus discrete logarithms:

Forward Operation (Easy): Given base g, exponent x, and modulus p, computing y = g^x \bmod p takes polynomial time O(\log x) using square-and-multiply.

Inverse Operation (Intractable): Given only g, y, and prime p, computing the exponent x = \log_g(y) \bmod p is computationally infeasible for sufficiently large primes (e.g. 2048+ bits).

2. Protocol Execution Steps

  1. Public Parameter Setup: Alice and Bob publicly agree on a large prime modulus p and a primitive generator g of the cyclic multiplicative group Z_p^*.
  2. Private Key Selection:
    • Alice selects a random private integer a such that 1 ≤ a < p.
    • Bob selects a random private integer b such that 1 ≤ b < p.
  3. Public Key Calculation & Exchange:
    • Alice computes public value A = g^a \bmod p and sends A across the network to Bob.
    • Bob computes public value B = g^b \bmod p and sends B across the network to Alice.
  4. Shared Secret Derivation:
    • Alice computes: K_A = B^a \bmod p = (g^b)^a \bmod p = g^{ab} \bmod p.
    • Bob computes: K_B = A^b \bmod p = (g^a)^b \bmod p = g^{ab} \bmod p.
    • Since g^{ab} \equiv g^{ba} \pmod{p}, both parties compute the identical secret key: K_A = K_B = K.

3. Man-in-the-Middle (MitM) Vulnerability

Basic Diffie-Hellman is unauthenticated. It establishes a shared secret with whoever is on the other end of the wire, but cannot prove who that party is.

If an active attacker (Eve) intercepts traffic on the channel:

  • Eve intercepts Alice's public value A and substitutes her own value E_A = g^e \bmod p to Bob.
  • Eve intercepts Bob's public value B and substitutes her own value E_B = g^e \bmod p to Alice.
  • Alice establishes a shared secret with Eve (K_{AE}); Bob establishes a separate shared secret with Eve (K_{EB}).
  • Eve transparently decrypts, reads, alters, and re-encrypts all communications without Alice or Bob knowing!

Simulation Procedure

  1. Navigate to the Practice tab.
  2. Review the public domain parameters: prime modulus p and generator g.
  3. Enter Alice's private secret a and Bob's private secret b (or use preset values).
  4. Click Execute Key Exchange Protocol.
  5. Inspect the animated exchange diagram: observe Alice transmitting A, Bob transmitting B, and both computing K_A and K_B.
  6. Verify that the shared secret agreement banner displays Shared Secrets Match: Valid Key Agreement.
  7. Toggle Simulate Active Man-in-the-Middle (Eve) Attack to observe how Eve splits the key exchange into two compromised sessions.

Canonical Classroom Demonstration

Standard textbook exchange using classroom parameters p=23 and g=5:

Public Parameters: p = 23, g = 5 (5 is a primitive root of 23)
Alice's Private Key: a = 6
Alice Computes Public Key A: A = 5^6 mod 23 = 15625 mod 23 = 8
Bob's Private Key: b = 15
Bob Computes Public Key B: B = 5^15 mod 23 = 19
Network Transmission: Alice sends A=8 to Bob; Bob sends B=19 to Alice.
Alice Derives Secret: K_A = B^a mod p = 19^6 mod 23 = 47045881 mod 23 = 2
Bob Derives Secret: K_B = A^b mod p = 8^15 mod 23 = 35184372088832 mod 23 = 2
✓ Shared Secret Agreement: K_A === K_B === 2

EXPERIMENT 09 Digital Signatures

Digital Signature Standard (DSS / DSA): Signing, Verification & Tamper Detection

Master the mathematical mechanics of the historical Digital Signature Algorithm (DSA - FIPS PUB 186-4), simulate signature generation and verification equations, observe tamper detection, and compare with modern Web Crypto ECDSA.

Standard Distinction
Algorithm Notice: Historical finite-field DSA is demonstrated mathematically below. Modern browser cryptography standards have transitioned to ECDSA (Elliptic Curve DSA) and Ed25519. Both the historical DSA mathematical engine and a modern Web Crypto ECDSA (P-256) demonstration are provided in this laboratory.

Aim of the Experiment

To analyze, simulate, and verify the Digital Signature Standard (DSS / DSA), evaluating key generation, ephemeral parameter selection, message digest signing, verification equations, and demonstrating how modifying a signed payload triggers immediate cryptographic rejection.

Key Learning Outcomes

  • Understand the tripartite security goals of digital signatures: origin authentication, data integrity, and non-repudiation.
  • Trace DSA key generation: domain parameters (p, q, g), private signing key x, and public verification key y.
  • Execute the DSA signature generation equations (r, s) and verification checks (w, u1, u2, v).
  • Demonstrate that altering a single character in the message causes the computed verification value v to mismatch r.
  • Execute a modern ECDSA (P-256 with SHA-256) signature workflow via the Web Crypto API.

Theoretical Principles of Digital Signatures

1. Foundational Security Objectives

While encryption ensures confidentiality, a digital signature provides mathematical proof of three distinct properties:

  • Authenticity: Confirms that the message was genuinely signed by the entity controlling the private key.
  • Integrity: Proves that the message has not been altered since it was signed.
  • Non-repudiation: The signer cannot plausibly dispute the validity of the signature, because only their private key could have produced it.

2. The Historical Digital Signature Algorithm (DSA)

Standardized in FIPS PUB 186 by NIST in 1994, DSA operates over finite cyclic groups:

1. Domain Parameters (Public):

  • p: A large prime modulus (e.g. 1024 to 3072 bits).
  • q: A prime divisor of (p - 1) (e.g. 160 or 256 bits).
  • g: A generator of subgroup of order q modulo p: g = h^{(p-1)/q} \bmod p > 1.

2. Key Generation:

  • Private Key (x): Select random integer 0 < x < q.
  • Public Key (y): Compute y = g^x \bmod p.

3. Signature Generation:

To sign message M with hash H(M):

  1. Select random per-message ephemeral integer k such that 0 < k < q.
  2. Compute r = (g^k \bmod p) \bmod q.
  3. Compute s = k^{-1} (H(M) + x \cdot r) \bmod q.
  4. The digital signature is the pair (r, s).

4. Signature Verification:

Given message M, public key y, and signature (r, s):

  1. Verify that 0 < r < q and 0 < s < q.
  2. Compute w = s^{-1} \bmod q.
  3. Compute u_1 = (H(M) \cdot w) \bmod q and u_2 = (r \cdot w) \bmod q.
  4. Compute verification value: v = ((g^{u_1} \cdot y^{u_2}) \bmod p) \bmod q.
  5. Validation: The signature is accepted as valid if and only if v == r.

3. The Critical Ephemeral Key (k) Rule

The value k must be cryptographically unpredictable and never reused. If an attacker observes two signatures (r, s_1) and (r, s_2) sharing the same k:
(s_1 - s_2) = k^{-1}(H_1 - H_2) \implies k = (H_1 - H_2)(s_1 - s_2)^{-1} \bmod q.
Once k is known, the signer's private key x can be computed directly: x = r^{-1}(s_1 \cdot k - H_1) \bmod q.

Simulation Procedure

  1. Navigate to the Practice tab.
  2. Section 1: Historical DSA Simulation:
    • Select domain parameters (e.g. p=79, q=13, g=2).
    • Observe the derived public key y = g^x \bmod p.
    • Enter a message (e.g. PAY $5000 TO UNIVERSITY).
    • Click Generate DSA Signature. Observe the calculated signature pair (r, s).
    • Click Verify Signature to inspect the intermediate calculations: w, u1, u2, v and confirm that v === r.
    • Tamper Test: Modify the message text (e.g. change $5000 to $9000) and click Verify Signature. Observe how the status updates to TAMPER DETECTED / INVALID SIGNATURE.
  3. Section 2: Modern Web Crypto ECDSA:
    • Click Generate ECDSA P-256 Keypair.
    • Sign an arbitrary message string using SHA-256.
    • Verify the signature and test message alterations with real Web Crypto validation.

Canonical DSA Classroom Demonstration

Textbook DSA signing with small parameters (p=79, q=13, g=2):

Domain Parameters: p = 79, q = 13 (13 divides 78), g = 2 (2^13 mod 79 = 1)
Private Key: x = 7 (0 < 7 < 13)
Public Key: y = g^x mod p = 2^7 mod 79 = 128 mod 79 = 49
Message: "HI" with hash H(m) = 5
Ephemeral Key: k = 3 (k^-1 mod 13 = 9)
Signature r: r = (2^3 mod 79) mod 13 = 8 mod 13 = 8
Signature s: s = 9 * (5 + 7*8) mod 13 = 9 * 61 mod 13 = 9 * 9 = 81 mod 13 = 3
Signature Pair: (r = 8, s = 3)
Verification w: w = 3^-1 mod 13 = 9
u1, u2: u1 = (5*9) mod 13 = 6, u2 = (8*9) mod 13 = 7
Verification v: v = ((2^6 * 49^7) mod 79) mod 13 = ((64 * 34) mod 79) mod 13 = 437 mod 13 = 8
✓ Verification: v (8) === r (8) -> VALID DIGITAL SIGNATURE

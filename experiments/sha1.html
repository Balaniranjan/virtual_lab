EXPERIMENT 07 Hashing & Integrity

Secure Hash Algorithm 1 (SHA-1): Digest Mechanics & Avalanche Analysis

Evaluate 160-bit cryptographic hash functions, investigate the Merkle-Damgård iterative compression structure, quantify the Avalanche Effect via bit Hamming distances, and review the 2017 SHAttered collision attack.

Deprecated for Signatures
Security Deprecation Notice: SHA-1 is cryptographically broken for collision resistance. Practical collisions were generated in 2017 ("SHAttered"). NIST has prohibited SHA-1 for digital signatures since 2011 and mandates full phase-out by December 31, 2030. Use SHA-256 or SHA-3 for modern security designs.

Aim of the Experiment

To calculate, analyze, and test message digests produced by the SHA-1 algorithm, differentiating one-way hashing from symmetric encryption, quantifying the Avalanche Effect across minor input mutations, and studying collision vulnerabilities.

Key Learning Outcomes

  • Differentiate between one-way hash functions (unkeyed, fixed-length digests) and encryption (keyed, reversible ciphers).
  • Compute standards-compatible 160-bit SHA-1 message digests (40 hexadecimal characters).
  • Inspect the Merkle-Damgård padding and 512-bit block compression across 80 round steps.
  • Measure the Avalanche Effect by calculating the exact bit difference (Hamming distance) between hashes of subtly different inputs.

Theoretical Principles of SHA-1

1. Hashing vs. Encryption

Characteristic Cryptographic Hash (e.g. SHA-1, SHA-256) Symmetric / Asymmetric Encryption
Directionality Strictly one-way (pre-image resistant) Two-way (reversible with decryption key)
Key Requirement No key required (deterministic public function) Mandatory secret or private key required
Output Length Strictly fixed length (160 bits for SHA-1) Variable (scales with plaintext block size)
Primary Purpose Data integrity verification & digital signatures Data confidentiality (privacy)

2. Algorithmic Architecture (FIPS PUB 180-1)

SHA-1 processes arbitrary-length messages up to 2^{64} - 1 bits in 512-bit blocks (16 words of 32 bits), producing a 160-bit digest.

  1. Padding: Append a single '1' bit, followed by necessary '0' bits until message length ≡ 448 mod 512. Then append a 64-bit integer representing original bit length.
  2. Chaining Variables: Five 32-bit registers initialized to constants:
    H_0 = 0x67452301, H_1 = 0xEFCDAB89, H_2 = 0x98BADCFE, H_3 = 0x10325476, H_4 = 0xC3D2E1F0.
  3. Message Expansion: Expand 16 words W_0 ... W_{15} into 80 words W_0 ... W_{79} via bitwise XOR and circular left rotation: W_t = S^1(W_{t-3} ⊕ W_{t-8} ⊕ W_{t-14} ⊕ W_{t-16}).
  4. 80 Round Steps: Four 20-step rounds applying different non-linear functions (Ch, Parity, Maj) and additive constants.

3. The 2017 "SHAttered" Collision Attack

In February 2017, researchers from CWI Amsterdam and Google announced SHAttered, the first practical collision attack against SHA-1. By performing approximately 9 \times 10^{18} SHA-1 computations, they generated two distinct PDF documents with different visual contents that yielded the identical SHA-1 hash digest:
38762cf7f55934b34d179ae6a4c80cadccbb7f0a.

Simulation Procedure

  1. Navigate to the Practice tab.
  2. Enter any ASCII text into the input message field.
  3. Click Calculate SHA-1 Digest.
  4. Examine the 40-character hexadecimal digest, length indicators (160 bits / 20 bytes), and copy the output.
  5. Avalanche Effect Experiment:
    • Enter two slightly different strings into Input A and Input B (e.g. The quick brown fox jumps over the lazy dog vs The quick brown fox jumps over the lazy cog).
    • Click Analyze Avalanche Effect.
    • Observe the exact number of flipped output bits (Hamming distance) and confirm that approximately 50% of bits change.
